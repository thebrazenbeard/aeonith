# Original synthetic literary-criticism pilot — source candidate only

The optional `training.synthetic_pilot` generator prepares **42 freshly
composed artificial microfiction passages** and their tentative, text-anchored
single-lens critiques. Its purpose is to exercise admission, tokenizer,
optimizer, adapter reload and evaluation **mechanics** on a controlled small
dataset. It is not human editorial instruction or a literary-competence
benchmark. No private manuscript, published novel, author biography, downloaded
book, benchmark stimulus or user personal data was ingested to prepare it.

## Corpus partition

| Partition | Distinct works | Scope |
| --- | ---: | --- |
| `train` | 28 | All 14 canonical lenses, two artificial stories per lens |
| `validation` | 7 | Separate story families, 7 lenses |
| `holdout` | 7 | Separate story families, the other 7 lenses |

The generator fixes the partition and byte order, checks unique IDs/sources,
literal quote anchoring and schema, and screens the passages for repeated or
near-duplicate text **across** partitions. This is lexical evidence only: it
does **not** establish unseen-task generalization, quality or a blind study.
Independent hostile review of the **initial** 42 targets found identical
limitations and synthesis prefixes, plus some lens/interpretation mismatches.
The revised generator now uses passage-specific lens notes and varied
limitations/synthesis, with structural regression tests; this is not a human
editorial validation. A semantically similar paraphrase of a training incident
still passed the lexical holdout screen in a falsification test. The holdout is
therefore for **mechanical smoke testing**, not evidence that new critique strategies
generalize. Any future effectiveness claim needs sequestered, disjoint task
families, templates and outcome rules plus frozen/shuffled-feedback controls.
The public literary-quality gate in `docs/LITERARY_QUALITY_GATE.md` is not
imported; its stimuli must never be trained on. The source repository contains
the generator's fictional ingredients but **no private candidate export**.

## Generate privately, without grants

On a qualified **native Linux** filesystem with an already-existing private
parent directory, choose a fresh destination *outside all Git checkouts*:

```bash
python -m training.synthetic_pilot --output /private/operator-space/synthetic-pilot-001
```

No network, model download, service restart, paid API or model training occurs.
The output is a new pinned mode-0700 private directory containing:

- `candidates.json` — `aeonith.candidate_corpus.v1`, status
  `REVIEW_PENDING_NOT_TRAINABLE`, all 42 records, and explicit
  `generator_provenance` indicating `model_generated_synthetic`.
- `generation_receipt.json` — exact candidate SHA-256, counts and limitations;
  no source passages or target text.

Both files use owner-only mode 0600 and cannot overwrite an existing export.
Windows and unqualified mounts fail closed until the production filesystem
custody boundary is verified. Do not redirect stdout into a Git worktree as
an alternate storage path.

## Admission, rights and operator control

Patrick explicitly authorized **generating and using original synthetic
material for a local pilot**. That instruction is *not* an attestation that
Patrick personally authored every passage, verified each critique's literary
quality, or approved public adapter distribution. The passages and critiques
were generated by an AI assistant, with no third-party passage included; the
generator therefore makes **no `self_authored` human claim**, grants no
rights, and creates no `sole_owner_decision` or fabricated identities.

The human-owner `training.admit_candidates` path rejects unsupported
ownership claims. A separate synthetic-generated admission mode now exists;
it requires an exact candidate SHA-256 plus an explicit later operator
decision for **private local training**, followed by a separate exact corpus
audit approval. See `training/SYNTHETIC_PILOT_ADMISSION.md`. Until those real
approvals are recorded, the candidate stays `REVIEW_PENDING_NOT_TRAINABLE`;
do not rename it to an approved plan or bypass either optimizer guard.

After an actual separately bound admission, keep validation and holdout
excluded from updates, record seeds, reload persisted adapter into a fresh
process and compare against frozen and shuffled-feedback controls. The tiny
pilot cannot support claims about literary ability, consciousness or overall
model improvement; human review and genuinely withheld literature are separate
studies. `generation_receipt.json` itself never proves a gradient occurred.
